# Deploying ccm-dashboard (AWS)

This app is a Vite (React) frontend + an Express/tRPC backend backed by MySQL.
It runs on AWS as a single **Lambda function inside a VPC**, fronted by an
**API Gateway HTTP API**, with data in **RDS for MySQL** (private) and AI note
generation via **Amazon Bedrock**. Every service used is HIPAA-eligible and
covered by the single AWS BAA.

## Architecture

| Piece | File / resource | Notes |
| ----- | --------------- | ----- |
| Lambda entry | [`server/_core/lambda.ts`](server/_core/lambda.ts) | Wraps the Express app with `serverless-http`. Serves **both** the API and the built React SPA (from `./public` inside the zip). |
| Shared app builder | [`server/_core/app.ts`](server/_core/app.ts) | Registers tRPC, OAuth, and the storage proxy. Used by both the local server and the Lambda. |
| Function bundle | `dist-lambda/index.mjs` | Generated by `pnpm run build:lambda` (esbuild, fully bundled ESM). |
| Public endpoint | API Gateway HTTP API → `https://<api-id>.execute-api.<region>.amazonaws.com` | Proxies every route to the Lambda. |
| Database | RDS for MySQL (`ccm-mysql`) | Private — reachable only from the Lambda's security group. Encrypted at rest, TLS in transit, deletion protection on. |
| AI notes | Amazon Bedrock (Claude, cross-region inference profile) | Enabled by setting `BEDROCK_MODEL_ID` on the Lambda. PHI stays in-VPC via a Bedrock VPC interface endpoint. |
| Env var reference | [`.env.example`](.env.example) | Every variable the app reads. |

> The concrete resource IDs (account, VPC, security groups, RDS endpoint,
> API Gateway id, Bedrock endpoint) are recorded outside the repo. Treat
> `.env` as the source of truth for this deployment; never commit it.

## Environment variables (set on the Lambda)

Configuration → Environment variables on the `ccm-app` function:

- `DATABASE_URL` — `mysql://USER:PASSWORD@<rds-endpoint>:3306/ccm`
- `JWT_SECRET` — long random string used to sign session cookies
- `OWNER_OPEN_ID` — openId of the owner/admin account
- `BEDROCK_MODEL_ID` — e.g. `us.anthropic.claude-haiku-4-5-20251001-v1:0` (omit to fall back to the Forge endpoint)
- `NODE_ENV=production`

The Lambda's IAM role supplies AWS credentials — no AWS keys go in env. The role
needs `bedrock:InvokeModel`, plus VPC access (`AWSLambdaVPCAccessExecutionRole`)
and CloudWatch Logs.

## Create / migrate the schema

From a machine that can reach the database (the RDS instance is private, so run
this from inside the VPC or via a temporary ingress rule for your IP):

```bash
pnpm drizzle-kit push --force   # creates/updates tables (do NOT use generate+migrate)
pnpm bootstrap:admin            # creates the owner admin from ADMIN_* env vars
```

> Use `drizzle-kit push`, not `db:push` (generate + migrate) — the repo's
> migration history is inconsistent and a fresh `generate` re-creates all tables,
> causing duplicate-table errors. `push` reconciles the live schema directly.

## Build & deploy an update

```powershell
pnpm install
pnpm run build:lambda                 # → dist-lambda/index.mjs (server, fully bundled)
pnpm exec vite build                  # → dist/public (the React SPA)

# lambda.ts serves ./public, so the built client goes next to index.mjs:
Copy-Item -Recurse -Force dist/public dist-lambda/public
Compress-Archive -Path dist-lambda/* -DestinationPath function.zip -Force

aws lambda update-function-code --function-name ccm-app --zip-file fileb://function.zip
aws lambda wait function-updated --function-name ccm-app
```

Then verify:

```powershell
# API health — expect 200 {"result":{"data":{"json":null}}}
curl https://<api-id>.execute-api.<region>.amazonaws.com/api/trpc/auth.me
```

## Notes & caveats

- **Serverless state is per-instance.** The in-memory login-attempt lockout in
  [`server/db.ts`](server/db.ts) and the cached DB connection live only for a warm
  instance, so brute-force protection is best-effort across instances. Move it to
  the database or a shared store if you need hard guarantees.
- **DB connections.** Each cold start opens a new mysql2 connection. Keep the
  Lambda's reserved concurrency modest, or front RDS with RDS Proxy, to avoid
  exhausting connections under load.
- **Manus OAuth.** `OAUTH_SERVER_URL` / `VITE_APP_ID` point at the Manus platform.
  Off-platform, the Manus OAuth sign-in won't complete, but email + password
  worker login (the primary auth path) works independently.
- **HIPAA.** Technical safeguards live in the app (bcrypt, RBAC, audit log, idle
  logout, TLS, error-message scrubbing). The organizational program (risk
  assessment, policies, workforce training) is still required before storing real
  PHI — see `HIPAA_COMPLIANCE.md`.
